# 贡献指南 / Contributing

> 中文在前，英文在后。Chinese first, English below.

## 中文

欢迎贡献！这个项目是羊毛空间（Yangmao Space）v14 的开源导出：前端源码 + 服务端源码 + 数据库迁移 + 数据快照。最有价值的贡献是**纠错**：过期的优惠、写错的额度、失效的链接。

### 可以做什么

- **纠正数据**：某条情报过期、额度写错、链接失效——请用 Issue 模板里的“数据纠正”提交，附上来源链接和正确信息。不要直接改 `data/` 下的快照文件，那是导出时生成的。
- **报 Bug**：用 “Bug 报告”模板，写清楚复现步骤和期望结果。
- **提功能**：用“功能请求”模板，先说问题再说方案。
- **改代码和文档**：Fork 仓库 → 新分支 → 改完提 PR。PR 描述里写清楚改了什么、为什么。

### 规矩

- **绝不提交密钥、token、密码或任何凭证**。仓库里不应该出现这些东西，CI 也会扫。
- 不要改 `data/` 下的快照（`getstate.json`、`posts.csv` 等），它们由导出流程生成；数据问题走 Issue。
- 匹配规则里的中文词表（`server/src/config.ts`、`server/src/rules.ts` 中的词表、正则、分类名）是功能性数据，改之前请先说明理由——翻错一个词会改变整库的分类。
- 代码只改注释和界面文案以外的逻辑时，请在 PR 里说明验证方法。

### 本地验证

改完后至少做到：

1. `data/` 下的 JSON 文件能正常解析；`posts.csv` 的行数与 `data/getstate.json` 里的总数对得上。
2. 没有新增中文硬编码混进英文界面文案（英文版包的规矩见英文版 README 的 Exceptions 一节）。
3. 没有引入新的密钥或凭证。

## English

Contributions are welcome! This project is the open-source export of Yangmao Space v14: client source + server source + database migrations + data snapshot. The most valuable contribution is **correcting data**: expired offers, wrong quotas, dead links.

### What you can do

- **Correct data**: if an offer is expired, a quota is wrong, or a link is dead, file an issue with the "Data correction" template, including the source link and the correct information. Do not edit the snapshot files under `data/` by hand — they are generated by the export process.
- **Report bugs**: use the "Bug report" template, with steps to reproduce and the expected result.
- **Request features**: use the "Feature request" template — problem first, then proposal.
- **Change code or docs**: fork the repo, create a branch, and open a PR. Describe what changed and why.

### Rules

- **Never commit secrets, tokens, passwords, or any credentials.** They do not belong in this repo, and CI scans for them.
- Do not edit snapshots under `data/` (`getstate.json`, `posts.csv`, etc.); they are generated by export. Report data problems via issues.
- The Chinese word lists in `server/src/config.ts` and `server/src/rules.ts` (word lists, regexes, category names) are functional matching data. Explain your reasoning before changing them — one wrong word changes classification across the whole library.
- If you change logic (not just comments or UI copy), describe how you verified it in the PR.

### Local checks

Before submitting, at least:

1. The JSON files under `data/` parse cleanly, and the row count of `posts.csv` matches the total in `data/getstate.json`.
2. No new hardcoded Chinese slips into English UI copy (see the Exceptions section of the English edition README).
3. No new secrets or credentials are introduced.
